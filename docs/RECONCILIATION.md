## 1. Executive Summary

`E:\tfo` is an active **React 19 + TypeScript + TanStack Start + Vite 8 + PlayCanvas 2.24** browser game originally ported from a Roblox/Luau prototype (`TitleUI.luau`, `SiteSelectUI.luau`, `ResultUI.luau` referenced in comments) and iterated through three Lovable milestones recorded in `.lovable/plan/*.md` (Moon physics & graphics, GDD rules/events, and a single-player four-outpost network).

Key baseline findings:

1. **Working core foundations exist:** Pure lunar movement/rover physics (`src/frontier/game/lunarPhysics.ts`), deterministic seeded rules (`src/frontier/game/rules.ts`), single-player four-outpost resource flow (`src/frontier/game/network.ts`), real-time + day-tick simulation (`src/frontier/game/simulation.ts`), PlayCanvas 3D scene (`src/frontier/game/playcanvasWorld.ts`), synthesized Web Audio + TTS (`src/frontier/game/soundEngine.ts`), and React UI overlays (`src/frontier/components/*`).
2. **Real online multiplayer is completely absent (`MISSING`):** `src/frontier/game/network.ts` is strictly an **in-game single-player four-outpost resource simulation**, not network transport. No Colyseus, WebSocket, WebRTC, or server room state exists anywhere in `package.json` or `src/`.
3. **Validation status:** Vitest (`31/31` tests across 4 files), `tsc --noEmit` (with `@ts-nocheck` present on 8 game files), and `vite build` **pass**. `npm run lint` **fails** (`1,069` errors, `6` warnings: `1,043` Prettier formatting mismatches, `8` `@ts-nocheck` bans, `13` `no-explicit-any`, `4` `prefer-const`, `1` `no-empty`).
4. **Confirmed runtime & gameplay bugs (`BROKEN`):** Live dev-server execution and code inspection confirmed leaked `window` listeners causing unhandled `TypeError` crashes on resize after React `<StrictMode>` remount, `404` failures on all Lovable-proxied `.glb` assets locally (leaving built Habitat/Farm/Lab 3D domes invisible), invisible 3D crystals for radar-discovered hidden ice deposits, an unrotated fixed-axis radar labeled `FWD` with no home-base marker, rover charging silently blocked while seated inside the rover, mission-stage desync after rover recovery or cross-day solar panel installation, and HUD daily deltas ignoring outpost network flow.
5. **Architectural/design conflicts (`CONFLICT`):** Several implemented mechanics conflict directly with Master Plan v2.0 (e.g., Base B "Power Lines" transmitting electricity between distant South Pole sites vs. the plan's ban on long-distance cables; all 4 sites placed ~360 m apart on a single 1,200 m map vs. distinct sites with hopper travel; instant game-over on O2 depletion and cargo loss on rover recovery vs. child-friendly recovery).
6. **Git status:** `E:\tfo` is **not currently a `.git` repository** (`git status` exits `128: fatal: not a git repository`). Version control initialization/remote linking must be confirmed before Phase 1 commits.

**Runtime Data Flow:**

1. Browser loads `/` (`src/routes/index.tsx`) -> `<ClientOnly>` lazy-loads `src/frontier/App.tsx`.
2. `App.tsx` subscribes to `gameSim` (`SimulationManager` singleton in `simulation.ts`) and instantiates `PlayCanvasLunarWorld` on `<canvas>`.
3. Player flows through `phase`: `'title'` (`TitleUI`) -> `'selecting'` (`SiteSelectUI`) -> `'landing'` (5s overlay) -> `'playing'` (`HUD` + active 3D loop) -> `'won' | 'lost'` (`ResultUI`).
4. During `'playing'`, `PlayCanvasLunarWorld.update(dt)` steps `lunarPhysics.ts`, writes player/rover coordinates and `prompt` directly onto `gameSim.state`, and triggers `gameSim` action methods (`installPanel`, `fillIce`, `unloadWater`, `startBuilding`, `buildFacility`, etc.) via `findAction()` (`E`/`R` tap or real-time hold).
5. `gameSim.update()` runs every `100 ms` via `window.setInterval`, advancing the `10s` lunar day timer, oxygen drain/refill, rover dock charging, airlock cycling, fact/tip queues, and daily colony/outpost ticks (`onDayTick()` -> `processEvents()` + `processNetwork()`), notifying React `HUD` subscribers on every tick.

## 4. How to Run the Game Locally

1. **Install dependencies:**
   - With Bun (matches `bun.lock` / `bunfig.toml`): `bun install`
   - With npm (if Bun is not installed): `npm install --no-package-lock`
2. **Start development server:**
   ```sh
   npm run dev
   ```
   Open `http://localhost:8080/` in a desktop WebGL2-capable browser.
3. **Preview production build:**
   ```sh
   npm run build
   npm run preview
   ```
4. **Local 3D Model Proxy Caveat (Important):**
   - `@lovable.dev/vite-tanstack-config` (`lovable:assets-proxy` plugin) only proxies `/__l5e/assets-v1/*` requests when the environment variable `LOVABLE_PREVIEW_HOST` (and optional `LOVABLE_PREVIEW_TOKEN`) is set.
   - Without `LOVABLE_PREVIEW_HOST`, all `.glb` requests return `404` locally. Primitive stand-ins keep the Lander, Rover, Astronaut, Solar Panels, Ice Crystals, and Outposts visible, **except** Modules A/B/C whose primitive domes are prematurely hidden before `loadModel()` completes (`playcanvasWorld.ts:804-805`).
5. **Dev Inspection Hooks:**
   - In `vite dev` (`import.meta.env.DEV`), `window.__world` (`PlayCanvasLunarWorld`) and `window.__gameSim` (`SimulationManager`) are exposed on `window` (`playcanvasWorld.ts:121`).

## 5. Existing Multiplayer Status vs. In-Game Base Network

It is critical to separate two similarly named concepts:

1. **In-Game Four-Base Resource Network (`EXISTS` / `PARTIAL` — Single-Player Only):**
   - Implemented in `src/frontier/game/network.ts` and `simulation.ts:743-804`, tested in `src/test/network.test.ts`.
   - Simulates 4 AI/automated unmanned outposts (`COMM`, `POWER`, `FOOD`, `EXPLORE`) placed around the player's main base on the same 3D map. Once unlocked, a solo player drives to each beacon, presses `E` to spend Energy/Water on 3 sequential stages, and wins by keeping all 4 outposts online for 5 consecutive days.
2. **Online Cooperative Multiplayer (`MISSING`):**
   - **Zero** multiplayer transport, server rooms, state synchronization, client prediction/interpolation, lobby/room codes, reconnection handling, quick-chat, pings, or role permissions exist anywhere in the repository.
   - `package.json` contains **no** `colyseus`, `colyseus.js`, `ws`, `socket.io`, `@supabase/supabase-js`, or WebRTC libraries.
   - `gameSim` (`src/frontier/game/simulation.ts:924`) is a single-player in-browser singleton mutated directly by `PlayCanvasLunarWorld` (`playcanvasWorld.ts:1010, 1054, 1078, 1103, 1106, 1217`).
   - `src/server.ts` and `src/start.ts` only handle TanStack Start SSR HTML rendering (configured for Cloudflare Workers via Nitro `cloudflare-module`), not persistent stateful multiplayer game rooms (unless paired with an external Colyseus Node/Container service or Durable Objects).

## 8. Confirmed Bugs vs. Potential Bug Reports (Plan §7 Verification)

Every potential bug listed in **Section 7** of the Master Plan was checked against the live codebase and dev server:

### A. Plan §7 Reported Bugs — Verification Verdict

1. **"Water or cargo disappearing when a rover is recovered." -> `CONFIRMED (CONFLICT + BROKEN)`**
   - **Evidence:** `simulation.ts:882-892` (`recoverRover()`) sets `rv.waterTank = 0` and toasts `'Rover recovered to base. Tank emptied, battery at 20%.'` while `playcanvasWorld.ts:1164` prompts `'Recall Rover (tank is lost)'`. Because `fillIce()` (`simulation.ts:620`) already subtracted the water from finite `site.deposit`, recovering a full rover permanently deletes up to `60W` from the world.
   - **Secondary Bug (`BROKEN`):** If `state.stage === 'unload'` when the player recovers the rover, `rv.waterTank` becomes `0` while `state.stage` stays `'unload'` (`"Return to base water refinery... press E to unload water"`), leaving the HUD objective pointing to an impossible action (`findAction()` requires `st.rover.waterTank > 0` at line 1149).

2. **"Oxygen recharging when an airlock should be sealed." -> `CONFIRMED (BROKEN / CONFLICT)`**
   - **Evidence 1 (Open rover refills O2 in vacuum):** `simulation.ts:325` checks `if (this.state.player.insideAirlock || this.state.player.inRover)` and refills O2 at `10%/s`, even though `initRover()` (`playcanvasWorld.ts:540`) is an unpressurized open-frame Lunar Terrain Vehicle, and even when the rover battery is `0` or chassis is broken!
   - **Evidence 2 (Damaged Habitat A & exterior Lander zone):** When Habitat A is `'damaged'` by micrometeors, `playcanvasWorld.ts:1031` (`distToLander < 8 && state.modules.A.status !== 'active'`) re-enables open-vacuum O2 refilling within 8 m outside the Lander, AND `playcanvasWorld.ts:946,1168` still allows opening and refilling O2 inside the damaged Habitat A airlock without repairing it first.
   - **Evidence 3 (Storms):** During an active radiation/solar storm (`state.activeStorm === true`), the airlock is never sealed or restricted.

3. **"Solar installation timing not matching the intended daily limits." -> `CONFIRMED (BROKEN)`**
   - **Evidence 1 (Cross-day HUD counter bug):** `HUD.tsx:12` renders `CONFIG.MISSION_TEXTS.installPanels.replace('{n}', `${3 - state.panelsInstalledToday}`)`. When a player installs 1 or 2 panels on Day 1 and the day ticks over (`onDayTick()` resets `panelsInstalledToday = 0` at `simulation.ts:406`), `stage` is still `'panels'` (requires `panelsInstalled >= 3` at `simulation.ts:570`), so the HUD resets to `"Deploy 3 solar panels"` even when only 1 more panel is needed.
   - **Evidence 2 (10-second day vs. 2-second hold pacing):** `CONFIG.DAY_SECONDS = 10` (`config.ts:87`) while `PANEL_HOLD = 2` (`rules.ts:17`, duplicated as `PANEL_INSTALL_HOLD = 2.0` in `config.ts:111`). Because a full "lunar day" passes every 10 real seconds, `panelsInstalledToday` resets almost as fast as the player can hold `E` three times (6s hold + movement), making the `PANELS_PER_DAY = 3` daily cap either invisible or confusingly out of sync with player actions.

4. **"Environmental events lacking clear player-facing effects." -> `CONFIRMED (PARTIAL)`**
   - **Evidence:** `HUD.tsx:264-273` shows a text banner and `simulation.ts` applies numeric multipliers (`0.5x` solar, `1.5x` O2 drain, suspended ice mining, or module/panel hit). However, `playcanvasWorld.ts` **never reads `activeStorm` or `eventBanner`** — sunlight intensity, sky, fog, dust, and visuals look 100% identical during a severe solar storm or micrometeor impact.

5. **"Insufficient terrain guidance." -> `CONFIRMED (BROKEN)`**
   - **Evidence:** `HUD.tsx:472-546` labels the top of the radar `FWD`, **but** computes blip positions with unrotated world coordinates `(x - ox, z - oz)` while the rover camera rotates behind `r.heading` (`playcanvasWorld.ts:1117`). Turning the rover does not rotate the radar, there is no player heading arrow, **Home Base `(0,0)` is not shown on the radar at all**, and there are no 3D waypoints/beacons for active objectives.

6. **"Rover charging behavior being unclear or inconsistent." -> `CONFIRMED (BROKEN)`**
   - **Evidence:** `simulation.ts:350` (`else if (!this.state.player.inRover)`) blocks charging while the player is driving/sitting in the rover on the dock. Driving onto the pad triggers the toast `"Rover docked at charging pad."`, yet battery stays frozen until the player presses `Space` to dismount — with **zero UI explanation** on the HUD or action prompt. Additionally, dead strings `MISSION_TEXTS.batteryEmpty` and `MISSION_TEXTS.roverBroken` (`config.ts:266-267`) are never displayed, and `CONFIG.ROVER.batteryMax` is mutated directly (`simulation.ts:790`).

### B. Additional Confirmed Bugs Discovered During Audit

7. **Unhandled `TypeError` crash on window resize & duplicate input listeners in `<StrictMode>` (`BROKEN`):**
   - `PlayCanvasLunarWorld` (`playcanvasWorld.ts:123,871-897`) registers anonymous `window` listeners (`resize`, `keydown`, `keyup`, `blur`) and never removes them in `destroy()`. Reproduced live in `vite dev`: resizing throws `TypeError: Cannot read properties of null (reading 'canvas')` on the destroyed first `<StrictMode>` instance, and HMR during `'playing'` leaves stale `keydown` handlers attached to `window`.
8. **All 3D `.glb` assets `404` locally & hide Module A/B/C buildings (`BROKEN`):**
   - Confirmed live in `vite dev`: without `LOVABLE_PREVIEW_HOST`, all `/__l5e/assets-v1/*.glb` requests `404`. Because `playcanvasWorld.ts:804-805` hides `BuildingStandIn` _before_ `loadModel()` succeeds, completed Habitat A, Farm B, and Research Lab C domes are invisible locally.
9. **Hidden ice sites (`101`, `102`) have no 3D visuals (`BROKEN`):**
   - `simulation.ts:786` appends `HIDDEN_ICE` when Base D Ground Radar is built, but `playcanvasWorld.ts:690` only builds 3D craters/crystals for initial `CONFIG.ICE_SITES` (`1..8`).
10. **HUD daily resource deltas ignore 4-base network flow (`BROKEN`):**
    - `simulation.ts:434-436` sets `dailyEnergyDelta`, `dailyWaterDelta`, and `dailyFoodDelta` before `processNetwork()` runs, omitting Base B power and Base C water/food output from the top-left resource panel.
11. **`selectSite` landing `setTimeout` is untracked (`BROKEN`):**
    - `simulation.ts:276` uses a raw `setTimeout(..., 5000)` without storing/clearing its timer ID in `pauseLoop()` or `restartGame()`.
12. **Outposts B & C build `"Airlock"` facilities that do not shelter/refill O2 (`PARTIAL` / inconsistency):**
    - `network.ts:23,25` names Facility 1 of Base B and Base C `'Airlock'`, costing `30E, 10W`, but `playcanvasWorld.ts:1031` only checks `HAB_DOOR` and `Lander` for oxygen refill.
